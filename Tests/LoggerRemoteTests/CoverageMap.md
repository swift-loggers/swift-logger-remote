# LoggerRemote Coverage Map

This file maps `LoggerRemote` contract areas to requirement IDs and
test coverage.

This document is non-normative and does not define behavior.
[`Docs/Requirements.md`](../../Docs/Requirements.md) owns requirement
IDs.

## Contract Coverage Index

| Contract area | Requirement IDs | Status | Primary test location |
| --- | --- | --- | --- |
| Durable delivery entry shape | LGR-1 | Covered | `RemoteDeliveryContractTests.swift` |
| Delivery result taxonomy | LGR-2 | Covered | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| Retry policy validation | LGR-3 | Covered | `RemoteDeliveryContractTests.swift` — factory validation pins attempt-count bounds (`1 ... maxSupportedAttempts`), constant backoff bounds (finite, `> 0`, `<= maxBackoffSeconds`), and exponential schedule bounds (`multiplier > 1`, `capSeconds >= initialSeconds`, `capSeconds <= maxBackoffSeconds`). Pure `delayBeforeRetry(attempt:)` calculation pins constant returns same seconds, exponential progresses as `initial * multiplier^(n - 1)`, exponential clamps at `capSeconds` during iterative growth, with defensive non-finite protection, and invalid attempts outside `1 ..< maxAttempts` throw `.invalidRetryPolicy`. `RetryExecutorTests.swift` adds the runtime per-entry retry semantics on top of the policy: first-attempt success, retryable-then-success, retryable budget exhausted, terminal stops immediately, thrown transport classified retryable, kind-inspecting classifier maps permanent failure to terminal, constant + exponential backoff sleep sequence through the injected sleep closure, `.invalidRetryDelay` on delay-calculation-seam failure (distinct from `.sleepInterrupted` — the policy-space and sleep-injector failures stay addressable separately), and `.sleepInterrupted` on sleep-injector failure between two retryable attempts. |
| Batch policy boundary behavior | LGR-4 | Covered | `RemoteDeliveryContractTests.swift` — boundary proof covers validated state (negative inputs and current-state-beyond-policy surface `.invalidBatchState`), overflow safety (entry-count and byte-count overflow fire the boundary instead of trapping), and oversized-single-entry rejection as `.batchSizeExceeded(limit:actual:)`. The boundary helper is engine-side machinery and is not part of the public API surface; the public contract model is the `RemoteBatchPolicy` value type. `BatchEngineTests.swift` adds the runtime batching application of this contract (deterministic count-cap and byte-cap splits, equal-to-cap fit + strictly-greater fire, oversized-single-entry rejection, accepted ordering from the byte-stable queue export preserved, duplicate identifiers preserved). |
| Sink-neutral transport surface | LGR-5 | Covered | `RemoteDeliveryContractTests.swift` (Sendable proof). `RetryExecutorTests.swift` + `ExecutionLoopTests.swift` exercise runtime conformance: every retry / loop attempt invokes one `RemoteTransport.send(payloadBytes:payloadMetadata:)` call per entry, the engine never aggregates entry bytes into a wire payload, and sink-owned `payloadMetadata` propagates byte-for-byte from `RemoteDeliveryEntry.metadata` to the transport call. The injected classifier owns the response-to-`RemoteDeliveryResult` mapping; the engine does not interpret response bytes, metadata, or transport error types. |
| Flush lifecycle vocabulary | LGR-6 | Future scope | The retry / execution loop type (`RetryExecutor` / `ExecutionLoop`) lands in PR 4/N; the flush-trigger vocabulary and lifecycle-observer surface stay PR 5/N and have no current public type or test. |
| Delivery error surface | LGR-7 | Covered | `RemoteDeliveryContractTests.swift` (Sendable proof + factory rejection paths); HTTP / vendor body codes stay out of the engine surface (verified in `RemoteBackendShapeTests.swift`) |
| Backend-shape sanity (Elastic `_bulk` + Splunk HEC) | LGR-8 | Covered | `RemoteBackendShapeTests.swift` |
| Vendor encoders/builders/validators stay in adapters | LGR-9 | Covered | `RemoteBackendShapeTests.swift` (classifiers are internal test fixtures, not engine API) |
| Persistence-owned ordering | LGR-10 | Covered | `DurableRemoteQueueTests.swift` — `DurableRemoteQueue` is the only `LoggerRemote` type that touches the persistence layer; enqueue wraps each `RemoteDeliveryEntry` into a package-owned internal queue record (identifier + payload + metadata) and persists it through `FileLogStore.append(_:)`. The queue assigns persistence `sequence` values from a private monotonic allocator so `RemoteDeliveryEntry.identifier` retains its correlation-only / no-ordering shape from PR 1/N. Tests prove the record round-trips losslessly across `drain(to:)` and that the persistence sequence is queue-assigned, not producer-derived. |
| Delivery acknowledgement is the only removal trigger | LGR-11 | Covered | `DurableRemoteQueueTests.swift` — `acknowledge()` is the sole API that consumes the in-memory removal boundary captured by `drain(to:)`. The queue holds one outstanding batch at a time (second `drain(to:)` before `acknowledge()` surfaces `.batchAlreadyOutstanding`), a failed `acknowledge()` keeps the outstanding batch for retry, and the queue never exposes a `retention` parameter so persistence retention cannot delete unacknowledged bytes. `ExecutionLoopTests.swift` proves that PR 4/N's `runOnce` does not advance the destructive-removal boundary for non-empty delivered queue payload batches (a second drain still surfaces `.batchAlreadyOutstanding`); the loop's empty-drain release short-circuits on `DurableRemoteQueueBatch.byteCount == 0` (before any export-file read) and calls `acknowledge()` on a zero-byte drain only, so no delivered queue payload bytes are removed and LGR-11 holds; the `emptyDrainShortCircuitsBeforeExportRead` test deletes the export artifact after the queue's authoritative zero-byte drain signal to prove the release path is keyed off the queue's byte-count signal rather than the export file. |

## Implementation File Index

| Source file | Covered contract areas | Primary test location |
| --- | --- | --- |
| `RemoteDeliveryEntry.swift` | Durable delivery entry shape, sink-owned metadata preservation, identifier correlation semantics (engine-local correlation only; participates in `Equatable` but carries no ordering contract and is not a persistence replay identity). | `RemoteDeliveryContractTests.swift` |
| `RemoteDeliveryResult.swift` | Delivery result taxonomy used by adapter classifiers | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| `RemoteRetryPolicy.swift` | Retry policy factory validation (locked attempt-count and backoff bounds), backoff schedule model, pure `delayBeforeRetry` calculation (engine-side machinery, not public API). Runtime retry execution is driven by `RetryExecutor` / `ExecutionLoop` (PR 4/N) on top of the validated policy and pure backoff calculation. | `RemoteDeliveryContractTests.swift`, `RetryExecutorTests.swift`, `ExecutionLoopTests.swift` |
| `RemoteBatchPolicy.swift` | Batch policy factory validation, deterministic boundary behavior, validated batching state, entry-count and byte-count overflow safety, oversized-single-entry rejection. Boundary helper is internal engine-side machinery, not public API. | `RemoteDeliveryContractTests.swift` |
| `RemoteTransport.swift` | Sink-neutral transport surface, transport response model (no HTTP status field; opaque response bytes and metadata preservation, default metadata is empty) | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| `RemoteDeliveryError.swift` | Typed sink-neutral diagnostic surface for adapter classification | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| `RemoteEngine.swift` | Current placeholder actor; no public dispatch surface yet | `RemoteDeliveryContractTests.swift` (constructibility proof only) |
| `DurableRemoteQueue.swift` | Persistence-backed durable queue core: enqueue wraps `RemoteDeliveryEntry` losslessly into an internal queue record and persists it under a queue-private sequence allocator; `flush()` forwards the persistence flush boundary and projects failure to `.flushFailed`; `drain(to:)` captures the recoverable prefix as a byte-stable export and admits one outstanding batch at a time; `acknowledge()` consumes the in-memory removal boundary captured by the most recent drain and keeps the boundary on retry-friendly failure; `currentOutstandingBatch()` exposes the held batch for the future delivery loop. No `retention` parameter so persistence retention cannot delete unacknowledged bytes. | `DurableRemoteQueueTests.swift` |
| `DurableRemoteQueueBatch.swift` | Value-typed drained-batch summary (export URL + exact post-export byte count) returned by `drain(to:)`. | `DurableRemoteQueueTests.swift` |
| `DurableRemoteQueueError.swift` | Typed diagnostic surface for queue lifecycle steps: outstanding-batch contract (`batchAlreadyOutstanding`), record-encoding defect, envelope validation, persistence append/flush/export/remove failures, and unmeasurable post-export byte counts. The `.flushFailed` case is distinct from `.enqueueFailed` (compile-time-checked in the test suite); runtime triggering of persistence-flush failure waits for an accessible flush seam in a future persistence release. | `DurableRemoteQueueTests.swift` |
| `DurableRemoteQueueRecord.swift` | Package-internal `Codable` record used by `DurableRemoteQueue` to round-trip `RemoteDeliveryEntry` (identifier + payload + metadata) across the persistence byte-stable export boundary. Intentionally not part of the public engine surface. | `DurableRemoteQueueTests.swift` (record-roundtrip proof through the decoded export) |
| `BatchEngine.swift` | Engine-internal batching machinery: `recoverEntries(from:)` parses a drained queue export into ordered `[RemoteDeliveryEntry]` (validates each envelope's `contentType` against the queue-owned constant fail-closed, then validates each queue record's `formatVersion` schema-evolution anchor fail-closed before decoding any other field); `makeBatches(from:policy:)` splits an entry stream into ordered batches under `RemoteBatchPolicy` (equal-to-cap fits, strictly-greater starts the next batch, oversized single entry surfaces `.batchSizeExceeded`). Accepted ordering from the byte-stable queue export and duplicate-identifier multiplicity preserved. Engine never calls `acknowledge()` or performs destructive removal. | `BatchEngineTests.swift` |
| `BatchEngineError.swift` | Typed diagnostic surface for the engine-internal parser: export-file read failure, byteCount mismatch, malformed envelope JSON, foreign envelope contentType, payload base64 / record JSON decode failure, and `formatVersion` missing or unknown. Engine-internal, not part of the public engine surface. | `BatchEngineTests.swift` |
| `RemoteDeliveryAttempt.swift` | Engine-internal per-entry retry outcome: the entry that was attempted, the final `RemoteDeliveryResult` once the budget was consumed (or `.success` / `.terminal` reached), and the number of attempts actually consumed (1-indexed, never above `policy.maxAttempts`). Not part of the public engine surface. | `RetryExecutorTests.swift`, `ExecutionLoopTests.swift` |
| `RetryExecutor.swift` | Engine-internal per-entry retry executor: drives one entry through the `RemoteRetryPolicy` budget, issues one `RemoteTransport.send(payloadBytes:payloadMetadata:)` call per attempt for the delivery entry without batch-level aggregation or shared retry state, matching Variant A per-entry dispatch semantics from PR 4/N, applies the injected classifier, sleep closure, and a `delayCalculator` seam that defaults to `RemoteRetryPolicy.delayBeforeRetry(attempt:)`. Returns one `RemoteDeliveryAttempt`. Never calls `acknowledge()` or performs destructive removal. Surfaces `ExecutionLoopError.invalidRetryDelay(_:)` when the delay-calculation seam refuses the requested attempt (engine-side or seam-injected invariant violation) and `ExecutionLoopError.sleepInterrupted` on sleep-injector failure between two retryable attempts; the two diagnostics stay distinct. | `RetryExecutorTests.swift` |
| `ExecutionLoop.swift` | Engine-internal one-shot execution loop: `runOnce(...)` drains the queue, recovers entries through `BatchEngine.recoverEntries(from:)`, splits them through `BatchEngine.makeBatches(from:policy:)`, and drives every entry through `RetryExecutor.deliver(...)` sequentially without shared retry state. Returns the ordered `[RemoteDeliveryAttempt]` across every batch in deterministic batch traversal order and entry traversal order within each batch, matching the drained export traversal order; an empty queue produces `[]`. Does NOT call `DurableRemoteQueue.acknowledge()` on a non-empty delivered queue payload batch — the acknowledgement-to-removal lifecycle for delivered queue payload bytes is wired in PR 5/N, so a non-empty drained-but-unacknowledged batch surfaces as `DurableRemoteQueueError.batchAlreadyOutstanding` on the next call. The empty-drain path short-circuits on the queue's authoritative `DurableRemoteQueueBatch.byteCount == 0` signal **before** invoking `BatchEngine.recoverEntries(from:)` — there is nothing to parse for the empty export because no delivered queue payload bytes exist in the drained export file — and calls `acknowledge()` immediately so the in-memory outstanding-batch boundary clears for the empty export despite no delivered queue payload bytes existing in the drained export file before returning `[]`. Keying the release off `byteCount == 0` rather than off "the recovered entry stream is empty" means a missing or unreadable export artifact after the queue's authoritative zero-byte drain signal cannot block this path; a polling caller does not get blocked by `DurableRemoteQueueError.batchAlreadyOutstanding` on the next empty pass. | `ExecutionLoopTests.swift` |
| `ExecutionLoopError.swift` | Typed diagnostic surface for the engine-internal retry / execution loop: drain failure, recovery failure, batch-split failure, retry-delay-calculation failure (engine-side / seam-injected invariant marker carrying the underlying `RemoteDeliveryError`), empty-drain release failure, and sleep-injector interruption. Engine-internal, not part of the public engine surface. The `sleepInterrupted` case drops the underlying error to keep the type `Equatable` for engine-internal test assertions; the engine treats every sleep-injector failure as the same outcome at this layer independent of the underlying thrown error for retry-loop lifecycle purposes. | `RetryExecutorTests.swift`, `ExecutionLoopTests.swift` |

## Maintenance Rules

- Keep this file as an index, not a second specification.
- Keep requirement IDs aligned with `Docs/Requirements.md`.
- Do not mark a future area as covered until its implementation and
  tests land.
- Backend-shape sanity coverage stays at least two non-equivalent
  models (Elastic `_bulk` + Splunk HEC); a third model can be added
  but not as a substitute.
