# LoggerRemote Coverage Map

This file maps `LoggerRemote` contract areas to requirement IDs and
test coverage.

This document is non-normative and does not define behavior.
[`Docs/Requirements.md`](../../Docs/Requirements.md) owns requirement
IDs.

## Contract Coverage Index

| Contract area | Requirement IDs | Status | Primary test location |
| --- | --- | --- | --- |
| Durable delivery entry shape | LGR-1 | Covered | `RemoteDeliveryContractTests.swift` |
| Delivery result taxonomy | LGR-2 | Covered | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| Retry policy validation | LGR-3 | Covered | `RemoteDeliveryContractTests.swift` — factory validation pins attempt-count bounds (`1 ... maxSupportedAttempts`), constant backoff bounds (finite, `> 0`, `<= maxBackoffSeconds`), and exponential schedule bounds (`multiplier > 1`, `capSeconds >= initialSeconds`, `capSeconds <= maxBackoffSeconds`). Pure `delayBeforeRetry(attempt:)` calculation pins constant returns same seconds, exponential progresses as `initial * multiplier^(n - 1)`, exponential clamps at `capSeconds` during iterative growth, with defensive non-finite protection, and invalid attempts outside `1 ..< maxAttempts` throw `.invalidRetryPolicy`. `BatchDispatchTests.swift` + `ExecutionLoopTests.swift` add the runtime batch-round retry semantics on top of the policy: per-entry attempt accounting (entry resolved on round 1 carries `attempts == 1`, entry retried through every round carries `attempts == maxAttempts`), active-set shrinking to retryables in subsequent rounds while preserving drained-export order, sleep between rounds wired through the injected sleep closure using each retained active entry's just-completed retryable attempt count, and `BatchDeliveryError.invalidRetryDelay(_:)` / `.sleepInterrupted` surfaced distinct from each other when their respective seams fail. |
| Batch policy boundary behavior | LGR-4 | Covered | `RemoteDeliveryContractTests.swift` — boundary proof covers validated state (negative inputs and current-state-beyond-policy surface `.invalidBatchState`), overflow safety (entry-count and byte-count overflow fire the boundary instead of trapping), and oversized-single-entry rejection as `.batchSizeExceeded(limit:actual:)`. The boundary helper is engine-side machinery and is not part of the public API surface; the public contract model is the `RemoteBatchPolicy` value type. `BatchEngineTests.swift` adds the runtime batching application of this contract (deterministic count-cap and byte-cap splits, equal-to-cap fit + strictly-greater fire, oversized-single-entry rejection, accepted ordering from the byte-stable queue export preserved, duplicate identifiers preserved). |
| Sink-neutral transport surface | LGR-5 | Covered | `RemoteDeliveryContractTests.swift` — Sendable + Equatable proofs cover `RemoteTransport`, `RemoteTransportBatchItem`, `RemoteTransportResponse`. `BatchDispatchTests.swift` + `ExecutionLoopTests.swift` + `RemoteEngineTests.swift` exercise runtime conformance against the batch-only primary dispatch contract: every dispatch round invokes one `RemoteTransport.sendBatch(_:)` call for the round's active items in their drained-export order; sink-owned `payloadMetadata` propagates byte-for-byte from `RemoteDeliveryEntry.metadata` into each `RemoteTransportBatchItem.payloadMetadata`; per-item classification through `RemoteTransport.classify(_:)` is deterministic and side-effect-free with respect to engine ack / export-file lifecycle state; the adapter owns both transport dispatch and delivery classification together. Single-event adapters dispatch each item independently inside their own `sendBatch` implementation; batch-aggregating adapters (Elastic `_bulk`, OTLP/HTTP batched) build one shared vendor request from the input array. |
| Flush lifecycle vocabulary | LGR-6 | Covered | `RemoteEngineTests.swift` — `RemoteEngine.flush()` is the caller-driven flush trigger; the engine owns no timer and no platform lifecycle observer. Coverage proves empty-queue flush returns zero attempts with the boundary acknowledged, sequential flushes drain freshly enqueued entries without blocking, all-success / all-terminal / mixed-resolved batches acknowledge, retryable-exhausted batches keep the boundary held, and sleep-injector failure surfaces `RemoteEngineError.retryInterrupted(.sleepInterrupted)`. Lifecycle integration on the host side (UIApplication / NSWorkspace / shutdown hooks) is documented in `Docs/APIDesign.md`. |
| Delivery error surface | LGR-7 | Covered | `RemoteDeliveryContractTests.swift` (Sendable + Equatable proofs + factory rejection paths); HTTP / vendor body codes stay out of the engine surface (verified in `RemoteBackendShapeTests.swift`). The public `RemoteEngineError` taxonomy (with `RemoteEngineParseError`, `RemoteEngineRetryError`, and `RemoteEngineExportCleanupContext` wrappers) keeps engine-internal `BatchEngineError` and `ExecutionLoopError` out of the public surface; `RemoteEngineTests.swift` + `BatchDispatchTests.swift` cover each mapping branch: `.drainFailed` (queue export-size reader seam), `.parseFailed(.recordPayloadMalformed)` (queue record-encoder seam injecting malformed bytes), `.batchFailed(.batchSizeExceeded(_:_:))` (tight `RemoteBatchPolicy` byte cap vs an oversized entry), `.retryInterrupted(.sleepInterrupted)` (sleep injector throws), `.acknowledgementFailed(_:)` (engine-internal acknowledge-override seam carrying a plausible persistence-layer remove failure), `.exportCleanupFailed(_:)` for both the `.emptyRelease` and `.acknowledgedNonEmpty` cleanup phases (engine-internal removal-override seam), and `.transportBatchInvalid(expected:actual:)` for an adapter `sendBatch(_:)` that returns the wrong result count. |
| Backend-shape sanity (Elastic `_bulk` + Splunk HEC) | LGR-8 | Covered | `RemoteBackendShapeTests.swift` |
| Vendor encoders/builders/validators stay in adapters | LGR-9 | Covered | `RemoteBackendShapeTests.swift` (classifiers are internal test fixtures, not engine API) |
| Persistence-owned ordering | LGR-10 | Covered | `DurableRemoteQueueTests.swift` — `DurableRemoteQueue` is the only `LoggerRemote` type that touches the persistence layer; enqueue wraps each `RemoteDeliveryEntry` into a package-owned internal queue record (identifier + payload + metadata) and persists it through `FileLogStore.append(_:)`. The queue assigns persistence `sequence` values from a private monotonic allocator so `RemoteDeliveryEntry.identifier` retains its correlation-only / no-ordering shape from PR 1/N. Tests prove the record round-trips losslessly across `drain(to:)` and that the persistence sequence is queue-assigned, not producer-derived. |
| Delivery acknowledgement is the only removal trigger | LGR-11 | Covered | `DurableRemoteQueueTests.swift` — `acknowledge()` is the sole API that consumes the in-memory removal boundary captured by `drain(to:)`. The queue holds one outstanding batch at a time (second `drain(to:)` before `acknowledge()` surfaces `.batchAlreadyOutstanding`), a failed `acknowledge()` keeps the outstanding batch for retry, and the queue never exposes a `retention` parameter so persistence retention cannot delete unacknowledged bytes. `ExecutionLoopTests.swift` proves PR 4/N's `runOnce` does not advance the destructive-removal boundary for non-empty delivered queue payload batches; the loop's empty-drain release short-circuits on `DurableRemoteQueueBatch.byteCount == 0` and calls `acknowledge()` on a zero-byte drain only. `RemoteEngineTests.swift` + `BatchDispatchTests.swift` cover the public ACK decision rule: the engine acknowledges only when **every recovered entry across the entire flush pass** is `.success` or `.terminal`; a single `.retryable`-exhausted outcome anywhere in the pass keeps the boundary held for the next flush. There is **no per-batch ACK** — ACK is a pass-wide decision computed after every batch's rounds resolve. `.terminal` is sink-decided permanent failure and counts as resolved, so ack happens; LGR-11 still holds because acknowledgement remains the only destructive-removal trigger. |

## Implementation File Index

| Source file | Covered contract areas | Primary test location |
| --- | --- | --- |
| `RemoteDeliveryEntry.swift` | Durable delivery entry shape, sink-owned metadata preservation, identifier correlation semantics (engine-local correlation only; participates in `Equatable` but carries no ordering contract and is not a persistence replay identity). | `RemoteDeliveryContractTests.swift` |
| `RemoteDeliveryResult.swift` | Delivery result taxonomy used by adapter classifiers | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| `RemoteRetryPolicy.swift` | Retry policy factory validation (locked attempt-count and backoff bounds), backoff schedule model, pure `delayBeforeRetry` calculation (engine-side machinery, not public API). Runtime retry execution is driven by the `ExecutionLoop` batch-round dispatcher (PR 4/N) on top of the validated policy and pure backoff calculation; `maxAttempts` bounds each entry's active dispatch rounds within a batch. | `RemoteDeliveryContractTests.swift`, `BatchDispatchTests.swift`, `ExecutionLoopTests.swift` |
| `RemoteBatchPolicy.swift` | Batch policy factory validation, deterministic boundary behavior, validated batching state, entry-count and byte-count overflow safety, oversized-single-entry rejection. Boundary helper is internal engine-side machinery, not public API. | `RemoteDeliveryContractTests.swift` |
| `RemoteTransport.swift` | Sink-neutral transport surface with `sendBatch(_:)` as the only dispatch primitive and `classify(_:)` for sink-owned per-item response-to-`RemoteDeliveryResult` mapping; the engine never inspects HTTP status, vendor body codes, or transport error types. The opaque transport response model has no HTTP status field; opaque response bytes and metadata preservation, default metadata is empty. `sendBatch(_:)` MUST return one `Result<RemoteTransportResponse, any Error>` per input `RemoteTransportBatchItem` in input order; a count mismatch is an adapter-contract violation surfaced fail-closed as `RemoteEngineError.transportBatchInvalid(expected:actual:)`. A whole-batch `sendBatch` throw routes every active item in the round through `classify(_:)` with the same `.failure(error)` value. `classify(_:)` is contractually deterministic for the same transport result within a flush pass and MUST NOT mutate the engine's acknowledgement or export-file lifecycle state directly or indirectly — it only maps a per-item send result to a delivery result. | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift`, `BatchDispatchTests.swift`, `ExecutionLoopTests.swift`, `RemoteEngineTests.swift` |
| `RemoteTransportBatchItem.swift` | Public per-item input shape `RemoteTransport.sendBatch(_:)` consumes: opaque pre-encoded `payloadBytes` plus sink-owned `payloadMetadata`. The engine builds one item per `RemoteDeliveryEntry` in the round's active set; the transport sees the entry's `payload` and `metadata` verbatim and never observes the engine-local `RemoteDeliveryEntry.identifier`. Per-item correlation between input items and the returned results array is by position, not by identifier. | `RemoteDeliveryContractTests.swift`, `BatchDispatchTests.swift` |
| `RemoteDeliveryError.swift` | Typed sink-neutral diagnostic surface for adapter classification | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| `RemoteEngine.swift` | Public delivery surface: caller-driven `flush()` actor. Each flush first consults `DurableRemoteQueue.currentOutstandingBatch()`: if the queue is still holding a batch the engine reuses that batch (and its already-written export file) through the outstanding-reuse path before any fresh flush/drain; otherwise it runs the fresh-drain path — `DurableRemoteQueue.flush()` followed by `DurableRemoteQueue.drain(to:)` into a fresh unique scratch file inside the caller-provided engine-exclusive directory. The engine then drives `BatchEngine.recoverEntries(from:)`, `BatchEngine.makeBatches(from:policy:)`, and per-batch batch-round dispatch against `RemoteTransport.sendBatch(_:)` with per-item classification through `RemoteTransport.classify(_:)`; round 1 of each batch dispatches every entry, each subsequent round re-dispatches only retryables in their original drained-export order until every entry resolves or `retryPolicy.maxAttempts` rounds are spent. ACK is **pass-wide**: the engine acknowledges only when every recovered entry across the entire flush pass is `.success` or `.terminal`; any `.retryable`-exhausted outcome anywhere holds the boundary so the next flush reuses the retained export artifact through the outstanding-reuse path. Export-file cleanup is keyed off the acknowledgement decision: drain failure before the engine owns a reusable drained batch reference for the current flush pass runs best-effort scratch cleanup with the `drainFailed` diagnostic kept primary; empty release and non-empty resolved + ack success both attempt to remove the export file and surface cleanup failures as `RemoteEngineError.exportCleanupFailed(_:)` only after the final acknowledgement state for the phase is already reached (cleanup failure does not retry already-acknowledged bytes — the retained artifact is a duplicate copy, never a retry source); every other path (any `.retryable`-exhausted outcome, or any parse / batch / retry-interruption / transport-batch-invalid / ack failure after the engine owns a reusable drained batch reference for the current flush pass) keeps the retained export artifact so the next flush reuses it through the outstanding-reuse path. The engine owns no timer and no platform lifecycle observer (LGR-3, LGR-6); host applications drive integration. Actor isolation serializes concurrent flushes. | `RemoteEngineTests.swift`, `BatchDispatchTests.swift` |
| `RemoteFlushSummary.swift` | Public sink-neutral summary returned by `RemoteEngine.flush()`: `attemptedBatches` (number of groups `BatchEngine.makeBatches(from:policy:)` produced for the flush pass; `0` on an empty drain because the empty-release path short-circuits before `BatchEngine.makeBatches(...)` runs over zero delivered queue payload bytes — an empty drain is not an attempted batch), per-classification entry counts (`attemptedEntries`, `succeededEntries`, `terminalEntries`, `retryableEntries`), and the `acknowledgement: RemoteFlushAcknowledgement` decision (`emptyReleased` for zero-byte drain, `removedDeliveredBytes` when every recovered entry is `.success` or `.terminal` and the engine ack succeeded, `notAcknowledged` when any `.retryable` outcome held the boundary). Carries no transport status codes, no vendor body details, and no per-entry diagnostics — those stay sink-owned. | `RemoteEngineTests.swift` |
| `RemoteEngineError.swift` | Public diagnostic surface for `RemoteEngine.flush()` (`flushFailed`, `drainFailed`, `parseFailed`, `batchFailed`, `retryInterrupted`, `acknowledgementFailed`, `exportCleanupFailed`, `transportBatchInvalid`) plus the public `RemoteEngineParseError` mirror of `BatchEngineError` (`exportFileReadFailed`, `exportByteCountMismatch`, `exportByteCountUnavailable`, `envelopeMalformed`, `envelopeContentTypeMismatch`, `recordPayloadBase64Invalid`, `recordPayloadMalformed`, `recordFormatVersionMissing`, `recordFormatVersionUnsupported`), `RemoteEngineRetryError` (`invalidRetryDelay`, `sleepInterrupted`), and `RemoteEngineExportCleanupContext` (`exportURL` + `phase` + `errorDomain` + `errorCode`) wrappers. The `drainFailed` case documents that it surfaces before the engine owns a reusable drained batch reference for the current flush pass. The `transportBatchInvalid(expected:actual:)` case carries the input item count vs the returned result count and surfaces when `RemoteTransport.sendBatch(_:)` violates its order-and-count contract; the queue keeps the outstanding-batch boundary so the next flush can reuse the retained export artifact through the outstanding-reuse path. The `exportCleanupFailed` case documents that the `acknowledgedNonEmpty` cleanup phase fires after the persistence layer has dropped the delivered queue payload bytes — acknowledgement is final and the retained artifact is a duplicate copy, never a retry source; cleanup failure MUST NOT trigger retry of already-acknowledged bytes, and callers MAY remove the retained URL after observing the case. The `emptyRelease` cleanup phase fires only after the empty-drain boundary has already been cleared by the engine ack; the release state is final, no delivered queue payload bytes existed, and a cleanup failure MUST NOT re-hold the empty boundary or retry the released empty pass — the lingering empty scratch artifact is a leftover the caller MAY remove. Engine-internal `BatchEngineError` and `ExecutionLoopError` types stay engine-internal; the engine translates them at the public boundary. | `RemoteEngineTests.swift`, `BatchDispatchTests.swift` |
| `DurableRemoteQueue.swift` | Persistence-backed durable queue core: enqueue wraps `RemoteDeliveryEntry` losslessly into an internal queue record and persists it under a queue-private sequence allocator; `flush()` forwards the persistence flush boundary and projects failure to `.flushFailed`; `drain(to:)` captures the recoverable prefix as a byte-stable export and admits one outstanding batch at a time; `acknowledge()` consumes the in-memory removal boundary captured by the most recent drain and keeps the boundary on retry-friendly failure; `currentOutstandingBatch()` exposes the held batch for `RemoteEngine.flush()` to drive its outstanding-reuse path. No `retention` parameter so persistence retention cannot delete unacknowledged bytes. | `DurableRemoteQueueTests.swift` |
| `DurableRemoteQueueBatch.swift` | Value-typed drained-batch summary (export URL + exact post-export byte count) returned by `drain(to:)`. | `DurableRemoteQueueTests.swift` |
| `DurableRemoteQueueError.swift` | Typed diagnostic surface for queue lifecycle steps: outstanding-batch contract (`batchAlreadyOutstanding`), record-encoding defect, envelope validation, persistence append/flush/export/remove failures, and unmeasurable post-export byte counts. The `.flushFailed` case is distinct from `.enqueueFailed` (compile-time-checked in the test suite); runtime triggering is not directly exercised because persistence `0.1.x` exposes no public flush-failure seam. | `DurableRemoteQueueTests.swift` |
| `DurableRemoteQueueRecord.swift` | Package-internal `Codable` record used by `DurableRemoteQueue` to round-trip `RemoteDeliveryEntry` (identifier + payload + metadata) across the persistence byte-stable export boundary. Intentionally not part of the public engine surface. | `DurableRemoteQueueTests.swift` (record-roundtrip proof through the decoded export) |
| `BatchEngine.swift` | Engine-internal batching machinery: `recoverEntries(from:)` parses a drained queue export into ordered `[RemoteDeliveryEntry]` (validates each envelope's `contentType` against the queue-owned constant fail-closed, then validates each queue record's `formatVersion` schema-evolution anchor fail-closed before decoding any other field); `makeBatches(from:policy:)` splits an entry stream into ordered batches under `RemoteBatchPolicy` (equal-to-cap fits, strictly-greater starts the next batch, oversized single entry surfaces `.batchSizeExceeded`). The batching loop also refuses fail-closed with `.invalidBatchState` if the boundary helper ever signals a split before a `current` batch exists — emitting an empty batch is a forbidden engine-side invariant, so the batcher does not rely on the helper's first-entry contract. Accepted ordering from the byte-stable queue export and duplicate-identifier multiplicity preserved. Engine never calls `acknowledge()` or performs destructive removal. | `BatchEngineTests.swift` |
| `BatchEngineError.swift` | Typed diagnostic surface for the engine-internal parser: export-file read failure, byteCount mismatch, malformed envelope JSON, foreign envelope contentType, payload base64 / record JSON decode failure, and `formatVersion` missing or unknown. Engine-internal, not part of the public engine surface. | `BatchEngineTests.swift` |
| `RemoteDeliveryAttempt.swift` | Engine-internal per-entry batch-dispatch outcome: the entry that was attempted, the final `RemoteDeliveryResult` once the round budget was consumed (or `.success` / `.terminal` reached), and the number of dispatch rounds the entry was active in (1-indexed, never above `policy.maxAttempts`). Not part of the public engine surface. | `BatchDispatchTests.swift`, `ExecutionLoopTests.swift` |
| `ExecutionLoop.swift` | Engine-internal one-shot execution loop: `runOnce(...)` drains the queue, recovers entries through `BatchEngine.recoverEntries(from:)`, splits them through `BatchEngine.makeBatches(from:policy:)`, and drives each batch through batch-round dispatch against `RemoteTransport.sendBatch(_:)`. Round 1 of each batch dispatches every entry; each subsequent round re-dispatches only the entries whose previous classification was `.retryable(reason:)`, preserving drained-export order in the next round's input array. Per-entry attempt counts equal the number of rounds the entry was active in. Sleep between rounds is wired through the injected `sleep` closure with `delayCalculator(retryPolicy, justCompletedRetryableAttemptCount)`; never fires before round 1 or after the final round. Whole-batch `sendBatch(_:)` throws are routed through `classify(_:)` with the same `.failure(error)` value for every active item in the round and count toward each item's budget. Adapter-contract count mismatch between input items and returned results surfaces fail-closed as `BatchDeliveryError.transportBatchCountMismatch(expected:actual:)` / `ExecutionLoopError.transportBatchCountMismatch(expected:actual:)`. Returns the ordered `[RemoteDeliveryAttempt]` across every batch in deterministic batch traversal order and entry traversal order within each batch, matching the drained export traversal order; an empty queue produces `[]`. Does NOT call `DurableRemoteQueue.acknowledge()` on a non-empty delivered queue payload batch; `RemoteEngine.flush()` owns that pass-wide acknowledgement-to-removal lifecycle, so a non-empty drained-but-unacknowledged batch surfaces as `DurableRemoteQueueError.batchAlreadyOutstanding` on the next direct `runOnce(...)` call. The empty-drain path short-circuits on the queue's authoritative `DurableRemoteQueueBatch.byteCount == 0` signal **before** invoking `BatchEngine.recoverEntries(from:)` and calls `acknowledge()` immediately so the in-memory outstanding-batch boundary clears for the empty export; keying the release off `byteCount == 0` rather than off "the recovered entry stream is empty" means a missing or unreadable export artifact after the queue's authoritative zero-byte drain signal cannot block the empty polling path. | `ExecutionLoopTests.swift`, `BatchDispatchTests.swift` |
| `ExecutionLoopError.swift` | Typed diagnostic surface for the engine-internal execution loop: drain failure, recovery failure, batch-split failure, retry-delay-calculation failure (engine-side / seam-injected invariant marker carrying the underlying `RemoteDeliveryError`), empty-drain release failure, sleep-injector interruption between batch rounds, internal batch-state invalidity (`internalBatchStateInvalid`) for engine-side active-set / outcome-tracking defects, and transport batch-response count mismatch (`transportBatchCountMismatch(expected:actual:)`). Engine-internal, not part of the public engine surface. The `sleepInterrupted` case drops the underlying error to keep the type `Equatable` for engine-internal test assertions; the engine treats every sleep-injector failure as the same outcome at this layer independent of the underlying thrown error for round-lifecycle purposes. | `ExecutionLoopTests.swift`, `BatchDispatchTests.swift` |
| `BatchDeliveryError.swift` | Engine-internal narrow failure surface raised by the shared `ExecutionLoop.deliver(batch:batchPolicy:retryPolicy:transport:sleep:delayCalculator:)` helper: recovery failure, batch-split failure, retry-delay-calculation failure, sleep-injector interruption between dispatch rounds, internal batch-state invalidity, and transport batch-response count mismatch. `RemoteEngine.flush()` projects each case onto a public `RemoteEngineError`; `ExecutionLoop.runOnce(...)` projects each case onto the broader `ExecutionLoopError` that also carries drain / empty-release cases. | `BatchDispatchTests.swift`, `ExecutionLoopTests.swift` |

## Maintenance Rules

- Keep this file as an index, not a second specification.
- Keep requirement IDs aligned with `Docs/Requirements.md`.
- Do not mark a future area as covered until its implementation and
  tests land.
- Backend-shape sanity coverage stays at least two non-equivalent
  models (Elastic `_bulk` + Splunk HEC); a third model can be added
  but not as a substitute.
