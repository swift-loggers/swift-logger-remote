# LoggerRemote Coverage Map

This file maps `LoggerRemote` contract areas to requirement IDs and
test coverage.

This document is non-normative and does not define behavior.
[`Docs/Requirements.md`](../../Docs/Requirements.md) owns requirement
IDs.

## Contract Coverage Index

| Contract area | Requirement IDs | Status | Primary test location |
| --- | --- | --- | --- |
| Durable delivery entry shape | LGR-1 | Covered | `RemoteDeliveryContractTests.swift` |
| Delivery result taxonomy | LGR-2 | Covered | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| Retry policy validation | LGR-3 | Covered | `RemoteDeliveryContractTests.swift` — factory validation pins attempt-count bounds (`1 ... maxSupportedAttempts`), constant backoff bounds (finite, `> 0`, `<= maxBackoffSeconds`), and exponential schedule bounds (`multiplier > 1`, `capSeconds >= initialSeconds`, `capSeconds <= maxBackoffSeconds`). Pure `delayBeforeRetry(attempt:)` calculation pins constant returns same seconds, exponential progresses as `initial * multiplier^(n - 1)`, exponential clamps at `capSeconds` during iterative growth, with defensive non-finite protection, and invalid attempts outside `1 ..< maxAttempts` throw `.invalidRetryPolicy`. `RetryExecutorTests.swift` adds the runtime per-entry retry semantics on top of the policy: first-attempt success, retryable-then-success, retryable budget exhausted, terminal stops immediately, thrown transport classified retryable, kind-inspecting classifier maps permanent failure to terminal, constant + exponential backoff sleep sequence through the injected sleep closure, `.invalidRetryDelay` on delay-calculation-seam failure (distinct from `.sleepInterrupted` — the policy-space and sleep-injector failures stay addressable separately), and `.sleepInterrupted` on sleep-injector failure between two retryable attempts. |
| Batch policy boundary behavior | LGR-4 | Covered | `RemoteDeliveryContractTests.swift` — boundary proof covers validated state (negative inputs and current-state-beyond-policy surface `.invalidBatchState`), overflow safety (entry-count and byte-count overflow fire the boundary instead of trapping), and oversized-single-entry rejection as `.batchSizeExceeded(limit:actual:)`. The boundary helper is engine-side machinery and is not part of the public API surface; the public contract model is the `RemoteBatchPolicy` value type. `BatchEngineTests.swift` adds the runtime batching application of this contract (deterministic count-cap and byte-cap splits, equal-to-cap fit + strictly-greater fire, oversized-single-entry rejection, accepted ordering from the byte-stable queue export preserved, duplicate identifiers preserved). |
| Sink-neutral transport surface | LGR-5 | Covered | `RemoteDeliveryContractTests.swift` (Sendable proof). `RetryExecutorTests.swift` + `ExecutionLoopTests.swift` + `RemoteEngineTests.swift` exercise runtime conformance: every retry / loop attempt invokes one `RemoteTransport.send(payloadBytes:payloadMetadata:)` call per entry, the engine never aggregates entry bytes into a wire payload, and sink-owned `payloadMetadata` propagates byte-for-byte from `RemoteDeliveryEntry.metadata` to the transport call. Classification moved onto the public `RemoteTransport.classify(_:)` method in PR 5/N so the adapter owns both `send` and classify together; the engine never inspects response bytes, metadata, or transport error types. |
| Flush lifecycle vocabulary | LGR-6 | Covered | `RemoteEngineTests.swift` — `RemoteEngine.flush()` is the caller-driven flush trigger; the engine owns no timer and no platform lifecycle observer. Coverage proves empty-queue flush returns zero attempts with the boundary acknowledged, sequential flushes drain freshly enqueued entries without blocking, all-success / all-terminal / mixed-resolved batches acknowledge, retryable-exhausted batches keep the boundary held, and sleep-injector failure surfaces `RemoteEngineError.retryInterrupted(.sleepInterrupted)`. Lifecycle integration on the host side (UIApplication / NSWorkspace / shutdown hooks) is documented in `Docs/APIDesign.md`. |
| Delivery error surface | LGR-7 | Covered | `RemoteDeliveryContractTests.swift` (Sendable proof + factory rejection paths); HTTP / vendor body codes stay out of the engine surface (verified in `RemoteBackendShapeTests.swift`). The public `RemoteEngineError` taxonomy (with `RemoteEngineParseError`, `RemoteEngineRetryError`, and `RemoteEngineExportCleanupContext` wrappers) keeps engine-internal `BatchEngineError` and `ExecutionLoopError` out of the public surface; `RemoteEngineTests.swift` covers each mapping branch: `.drainFailed` (queue export-size reader seam), `.parseFailed(.recordPayloadMalformed)` (queue record-encoder seam injecting malformed bytes), `.batchFailed(.batchSizeExceeded(_:_:))` (tight `RemoteBatchPolicy` byte cap vs an oversized entry), `.retryInterrupted(.sleepInterrupted)` (sleep injector throws), `.acknowledgementFailed(_:)` (engine-internal acknowledge-override seam carrying a plausible persistence-layer remove failure), and `.exportCleanupFailed(_:)` for both the `.emptyRelease` and `.acknowledgedNonEmpty` cleanup phases (engine-internal removal-override seam). |
| Backend-shape sanity (Elastic `_bulk` + Splunk HEC) | LGR-8 | Covered | `RemoteBackendShapeTests.swift` |
| Vendor encoders/builders/validators stay in adapters | LGR-9 | Covered | `RemoteBackendShapeTests.swift` (classifiers are internal test fixtures, not engine API) |
| Persistence-owned ordering | LGR-10 | Covered | `DurableRemoteQueueTests.swift` — `DurableRemoteQueue` is the only `LoggerRemote` type that touches the persistence layer; enqueue wraps each `RemoteDeliveryEntry` into a package-owned internal queue record (identifier + payload + metadata) and persists it through `FileLogStore.append(_:)`. The queue assigns persistence `sequence` values from a private monotonic allocator so `RemoteDeliveryEntry.identifier` retains its correlation-only / no-ordering shape from PR 1/N. Tests prove the record round-trips losslessly across `drain(to:)` and that the persistence sequence is queue-assigned, not producer-derived. |
| Delivery acknowledgement is the only removal trigger | LGR-11 | Covered | `DurableRemoteQueueTests.swift` — `acknowledge()` is the sole API that consumes the in-memory removal boundary captured by `drain(to:)`. The queue holds one outstanding batch at a time (second `drain(to:)` before `acknowledge()` surfaces `.batchAlreadyOutstanding`), a failed `acknowledge()` keeps the outstanding batch for retry, and the queue never exposes a `retention` parameter so persistence retention cannot delete unacknowledged bytes. `ExecutionLoopTests.swift` proves PR 4/N's `runOnce` does not advance the destructive-removal boundary for non-empty delivered queue payload batches; the loop's empty-drain release short-circuits on `DurableRemoteQueueBatch.byteCount == 0` and calls `acknowledge()` on a zero-byte drain only. `RemoteEngineTests.swift` covers PR 5/N's acknowledgement decision rule: the engine acknowledges the drained batch only when every recovered entry is `.success` or `.terminal`; a single `.retryable`-exhausted outcome keeps the boundary held so the next flush retries the same bytes (verified by a follow-up drain surfacing `.batchAlreadyOutstanding`). `.terminal` is sink-decided permanent failure and counts as resolved, so ack happens; LGR-11 still holds because acknowledgement remains the only destructive-removal trigger. |

## Implementation File Index

| Source file | Covered contract areas | Primary test location |
| --- | --- | --- |
| `RemoteDeliveryEntry.swift` | Durable delivery entry shape, sink-owned metadata preservation, identifier correlation semantics (engine-local correlation only; participates in `Equatable` but carries no ordering contract and is not a persistence replay identity). | `RemoteDeliveryContractTests.swift` |
| `RemoteDeliveryResult.swift` | Delivery result taxonomy used by adapter classifiers | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| `RemoteRetryPolicy.swift` | Retry policy factory validation (locked attempt-count and backoff bounds), backoff schedule model, pure `delayBeforeRetry` calculation (engine-side machinery, not public API). Runtime retry execution is driven by `RetryExecutor` / `ExecutionLoop` (PR 4/N) on top of the validated policy and pure backoff calculation. | `RemoteDeliveryContractTests.swift`, `RetryExecutorTests.swift`, `ExecutionLoopTests.swift` |
| `RemoteBatchPolicy.swift` | Batch policy factory validation, deterministic boundary behavior, validated batching state, entry-count and byte-count overflow safety, oversized-single-entry rejection. Boundary helper is internal engine-side machinery, not public API. | `RemoteDeliveryContractTests.swift` |
| `RemoteTransport.swift` | Sink-neutral transport surface with `send(payloadBytes:payloadMetadata:)` and `classify(_:)` (sink-owned response-to-`RemoteDeliveryResult` mapping; the engine never inspects HTTP status, vendor body codes, or transport error types) plus the opaque transport response model (no HTTP status field; opaque response bytes and metadata preservation, default metadata is empty). `classify(_:)` is contractually deterministic for the same transport result within a flush pass and MUST NOT mutate the engine's acknowledgement or export-file lifecycle state — it only maps a send result to a delivery result. | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift`, `RetryExecutorTests.swift`, `ExecutionLoopTests.swift`, `RemoteEngineTests.swift` |
| `RemoteDeliveryError.swift` | Typed sink-neutral diagnostic surface for adapter classification | `RemoteDeliveryContractTests.swift`, `RemoteBackendShapeTests.swift` |
| `RemoteEngine.swift` | Public delivery surface: caller-driven `flush()` actor. Each flush first consults `DurableRemoteQueue.currentOutstandingBatch()`: if the queue is still holding a batch the engine reuses that batch (and its already-written export file) through the outstanding-reuse path before any fresh flush/drain; otherwise it runs the fresh-drain path — `DurableRemoteQueue.flush()` followed by `DurableRemoteQueue.drain(to:)` into a fresh unique scratch file inside the caller-provided engine-exclusive directory. The engine then drives `BatchEngine.recoverEntries(from:)`, `BatchEngine.makeBatches(from:policy:)`, and per-entry `RetryExecutor.deliver(...)`, and decides acknowledgement based on the per-classification tally — ack iff every recovered entry is `.success` or `.terminal`; any `.retryable`-exhausted outcome holds the boundary so the next flush replays the retained export artifact through the outstanding-reuse path. Export-file cleanup is keyed off the acknowledgement decision: drain failure before the engine owns a reusable drained batch reference for the current flush pass runs best-effort scratch cleanup with the `drainFailed` diagnostic kept primary; empty release and non-empty resolved + ack success both remove the export file and surface cleanup failures as `RemoteEngineError.exportCleanupFailed(_:)` only after the final acknowledgement state for the phase is already reached (cleanup failure does not retry already-acknowledged bytes — the retained artifact is a duplicate copy, never a retry source); every other path (any `.retryable`-exhausted outcome, or any parse / batch / retry-interruption / ack failure after the engine owns a reusable drained batch reference for the current flush pass) keeps the retained export artifact so the next flush replays it through the outstanding-reuse path. The engine owns no timer and no platform lifecycle observer (LGR-3, LGR-6); host applications drive integration. Actor isolation serializes concurrent flushes. | `RemoteEngineTests.swift` |
| `RemoteFlushSummary.swift` | Public sink-neutral summary returned by `RemoteEngine.flush()`: `attemptedBatches` (number of groups `BatchEngine.makeBatches(from:policy:)` produced for the flush pass; `0` on an empty drain because the empty-release path short-circuits before `BatchEngine.makeBatches(...)` runs over zero delivered queue payload bytes — an empty drain is not an attempted batch), per-classification entry counts (`attemptedEntries`, `succeededEntries`, `terminalEntries`, `retryableEntries`), and the `acknowledgement: RemoteFlushAcknowledgement` decision (`emptyReleased` for zero-byte drain, `removedDeliveredBytes` when every recovered entry is `.success` or `.terminal` and the engine ack succeeded, `notAcknowledged` when any `.retryable` outcome held the boundary). Carries no transport status codes, no vendor body details, and no per-entry diagnostics — those stay sink-owned. | `RemoteEngineTests.swift` |
| `RemoteEngineError.swift` | Public diagnostic surface for `RemoteEngine.flush()` (`flushFailed`, `drainFailed`, `parseFailed`, `batchFailed`, `retryInterrupted`, `acknowledgementFailed`, `exportCleanupFailed`) plus the public `RemoteEngineParseError` mirror of `BatchEngineError` (`exportFileReadFailed`, `exportByteCountMismatch`, `exportByteCountUnavailable`, `envelopeMalformed`, `envelopeContentTypeMismatch`, `recordPayloadBase64Invalid`, `recordPayloadMalformed`, `recordFormatVersionMissing`, `recordFormatVersionUnsupported`), `RemoteEngineRetryError` (`invalidRetryDelay`, `sleepInterrupted`), and `RemoteEngineExportCleanupContext` (`exportURL` + `phase` + `errorDomain` + `errorCode`) wrappers. The `drainFailed` case documents that it surfaces before the engine owns a reusable drained batch reference for the current flush pass. The `exportCleanupFailed` case documents that the `acknowledgedNonEmpty` cleanup phase fires after the persistence layer has dropped the delivered queue payload bytes — acknowledgement is final and the retained artifact is a duplicate copy, never a retry source; cleanup failure MUST NOT trigger retry of already-acknowledged bytes, and callers MAY remove the retained URL after observing the case. The `emptyRelease` cleanup phase fires only after the empty-drain boundary has already been cleared by the engine ack; the release state is final, no delivered queue payload bytes existed, and a cleanup failure MUST NOT re-hold the empty boundary or retry the released empty pass — the lingering empty scratch artifact is a leftover the caller MAY remove. Engine-internal `BatchEngineError` and `ExecutionLoopError` types stay engine-internal; the engine translates them at the public boundary. | `RemoteEngineTests.swift` |
| `DurableRemoteQueue.swift` | Persistence-backed durable queue core: enqueue wraps `RemoteDeliveryEntry` losslessly into an internal queue record and persists it under a queue-private sequence allocator; `flush()` forwards the persistence flush boundary and projects failure to `.flushFailed`; `drain(to:)` captures the recoverable prefix as a byte-stable export and admits one outstanding batch at a time; `acknowledge()` consumes the in-memory removal boundary captured by the most recent drain and keeps the boundary on retry-friendly failure; `currentOutstandingBatch()` exposes the held batch for `RemoteEngine.flush()` to drive its outstanding-reuse path. No `retention` parameter so persistence retention cannot delete unacknowledged bytes. | `DurableRemoteQueueTests.swift` |
| `DurableRemoteQueueBatch.swift` | Value-typed drained-batch summary (export URL + exact post-export byte count) returned by `drain(to:)`. | `DurableRemoteQueueTests.swift` |
| `DurableRemoteQueueError.swift` | Typed diagnostic surface for queue lifecycle steps: outstanding-batch contract (`batchAlreadyOutstanding`), record-encoding defect, envelope validation, persistence append/flush/export/remove failures, and unmeasurable post-export byte counts. The `.flushFailed` case is distinct from `.enqueueFailed` (compile-time-checked in the test suite); runtime triggering of persistence-flush failure waits for an accessible flush seam in a future persistence release. | `DurableRemoteQueueTests.swift` |
| `DurableRemoteQueueRecord.swift` | Package-internal `Codable` record used by `DurableRemoteQueue` to round-trip `RemoteDeliveryEntry` (identifier + payload + metadata) across the persistence byte-stable export boundary. Intentionally not part of the public engine surface. | `DurableRemoteQueueTests.swift` (record-roundtrip proof through the decoded export) |
| `BatchEngine.swift` | Engine-internal batching machinery: `recoverEntries(from:)` parses a drained queue export into ordered `[RemoteDeliveryEntry]` (validates each envelope's `contentType` against the queue-owned constant fail-closed, then validates each queue record's `formatVersion` schema-evolution anchor fail-closed before decoding any other field); `makeBatches(from:policy:)` splits an entry stream into ordered batches under `RemoteBatchPolicy` (equal-to-cap fits, strictly-greater starts the next batch, oversized single entry surfaces `.batchSizeExceeded`). The batching loop also refuses fail-closed with `.invalidBatchState` if the boundary helper ever signals a split before a `current` batch exists — emitting an empty batch is a forbidden engine-side invariant, so the batcher does not rely on the helper's first-entry contract. Accepted ordering from the byte-stable queue export and duplicate-identifier multiplicity preserved. Engine never calls `acknowledge()` or performs destructive removal. | `BatchEngineTests.swift` |
| `BatchEngineError.swift` | Typed diagnostic surface for the engine-internal parser: export-file read failure, byteCount mismatch, malformed envelope JSON, foreign envelope contentType, payload base64 / record JSON decode failure, and `formatVersion` missing or unknown. Engine-internal, not part of the public engine surface. | `BatchEngineTests.swift` |
| `RemoteDeliveryAttempt.swift` | Engine-internal per-entry retry outcome: the entry that was attempted, the final `RemoteDeliveryResult` once the budget was consumed (or `.success` / `.terminal` reached), and the number of attempts actually consumed (1-indexed, never above `policy.maxAttempts`). Not part of the public engine surface. | `RetryExecutorTests.swift`, `ExecutionLoopTests.swift` |
| `RetryExecutor.swift` | Engine-internal per-entry retry executor: drives one entry through the `RemoteRetryPolicy` budget, issues one `RemoteTransport.send(payloadBytes:payloadMetadata:)` call per attempt for the delivery entry without batch-level aggregation or shared retry state, matching Variant A per-entry dispatch semantics from PR 4/N, applies the injected classifier, sleep closure, and a `delayCalculator` seam that defaults to `RemoteRetryPolicy.delayBeforeRetry(attempt:)`. Returns one `RemoteDeliveryAttempt`. Never calls `acknowledge()` or performs destructive removal. Surfaces `BatchDeliveryError.invalidRetryDelay(_:)` when the delay-calculation seam refuses the requested attempt (engine-side or seam-injected invariant violation) and `BatchDeliveryError.sleepInterrupted` on sleep-injector failure between two retryable attempts; the two diagnostics stay distinct. The broader `ExecutionLoopError` surface is reached only at the `ExecutionLoop.runOnce(...)` mapping layer above this helper. | `RetryExecutorTests.swift` |
| `ExecutionLoop.swift` | Engine-internal one-shot execution loop: `runOnce(...)` drains the queue, recovers entries through `BatchEngine.recoverEntries(from:)`, splits them through `BatchEngine.makeBatches(from:policy:)`, and drives every entry through `RetryExecutor.deliver(...)` sequentially without shared retry state and without batch-level transport aggregation. Returns the ordered `[RemoteDeliveryAttempt]` across every batch in deterministic batch traversal order and entry traversal order within each batch, matching the drained export traversal order; an empty queue produces `[]`. Does NOT call `DurableRemoteQueue.acknowledge()` on a non-empty delivered queue payload batch; `RemoteEngine.flush()` owns that acknowledgement-to-removal lifecycle for delivered queue payload bytes, so a non-empty drained-but-unacknowledged batch surfaces as `DurableRemoteQueueError.batchAlreadyOutstanding` on the next direct `runOnce(...)` call. The empty-drain path short-circuits on the queue's authoritative `DurableRemoteQueueBatch.byteCount == 0` signal **before** invoking `BatchEngine.recoverEntries(from:)` — there is nothing to parse for the empty export because no delivered queue payload bytes exist in the drained export file — and calls `acknowledge()` immediately so the in-memory outstanding-batch boundary clears for the empty export despite no delivered queue payload bytes existing in the drained export file before returning `[]`. Keying the release off `byteCount == 0` rather than off "the recovered entry stream is empty" means a missing or unreadable export artifact after the queue's authoritative zero-byte drain signal cannot block this path; a polling caller does not get blocked by `DurableRemoteQueueError.batchAlreadyOutstanding` on the next empty pass. | `ExecutionLoopTests.swift` |
| `ExecutionLoopError.swift` | Typed diagnostic surface for the engine-internal retry / execution loop: drain failure, recovery failure, batch-split failure, retry-delay-calculation failure (engine-side / seam-injected invariant marker carrying the underlying `RemoteDeliveryError`), empty-drain release failure, and sleep-injector interruption. Engine-internal, not part of the public engine surface. The `sleepInterrupted` case drops the underlying error to keep the type `Equatable` for engine-internal test assertions; the engine treats every sleep-injector failure as the same outcome at this layer independent of the underlying thrown error for retry-loop lifecycle purposes. | `RetryExecutorTests.swift`, `ExecutionLoopTests.swift` |

## Maintenance Rules

- Keep this file as an index, not a second specification.
- Keep requirement IDs aligned with `Docs/Requirements.md`.
- Do not mark a future area as covered until its implementation and
  tests land.
- Backend-shape sanity coverage stays at least two non-equivalent
  models (Elastic `_bulk` + Splunk HEC); a third model can be added
  but not as a substitute.
